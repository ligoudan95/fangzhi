## 1. 评审范围与原则

1. 增量不破坏既有 14 表导出与对拍；新表 PK 即刻注册，业务校验随逻辑落地逐步收紧。
2. 所有引用走 `ref<T>`；枚举只尾部追加。
3. Phase 0 只落当前阶段实际消费的字段；为 Phase 1+ 预留但不实现行为的字段不加（避免死字段）。

## 2. Phase A：作物生产闭环（本批）

### 2.1 新表 `ItemBase.csv`（物品主档）

| 行 | 值 |
|---|---|
| 字段 | `itemId,name,kind,storageCategory` |
| 类型 | `int,string,enum<ItemKind>,ref<StorageRule>` |
| 可见性 | `c,c,c,c` |
| 注释 | `主键,物品名,物品类别,仓储分类（容量归属）` |

Phase A 落地作物产物 4 行 + 兽贝/灵晶不入 ItemBase（货币走 wallet，docs/15 §3.2）。`ItemKind` 枚举仅 `1 材料` 一档起步。

### 2.2 新表 `StorageRule.csv`（仓储容量）

| 行 | 值 |
|---|---|
| 字段 | `categoryId,baseCap` |
| 类型 | `int,int` |
| 可见性 | `c,c` |
| 注释 | `主键（1矿石2草药3食物4金属锭5建材）,基础容量（软上限）` |

docs/05 §11 基准：200/150/100/100/150。软容量语义：可超上限保留，每满 24h 衰减 10%（docs/15 §2.4）；仓库等级扩容公式 `base×1.5^(level-1)` 属 Building 联动，Phase A 仅落基础容量。

### 2.3 新表 `SeasonWeather.csv`（四季系数）

| 行 | 值 |
|---|---|
| 字段 | `seasonId,name,farmMult,mineMult,beastMult` |
| 类型 | `int,string,float,float,float` |
| 可见性 | `c,c,c,c,c` |
| 注释 | `主键（0春1夏2秋3冬）,季节名,灵田产量系数,矿场系数,凶兽潮系数` |

docs/05 §8：春 ×1.2 / 夏 ×1.0 / 秋 ×1.3 / 冬 ×0.5（矿场另值）。天气随机事件不入 Phase A（docs/15 §2.6）。

### 2.4 `Crop.csv` 扩展

新增列 `outputItemId:ref<ItemBase>,outputCount:int`（产物与数量）；补齐 docs/05 §5 全 7 行（玄冰苔、千年桃木）。既有 4 行回填产物指向。

### 2.5 `GlobalConst.csv` 新键

| 键 | 值 | 依据 |
|---|---|---|
| `SEASON_EPOCH_UTC_SEC` | 1735689600（2025-01-01T00:00Z） | 全局季纪元（docs/15 §1.3；所有档同季） |
| `OFFLINE_CAP_BASE_SEC` | 43200 | 12h 基础上限（docs/15 §2.2） |
| `OFFLINE_CAP_TOTEM_SEC` | 86400 | 图腾二段 24h |
| `STORAGE_DECAY_PCT` | 0.1 | 溢出 24h 衰减 10% |
| `STORAGE_DECAY_PERIOD_SEC` | 86400 | 衰减周期 |

### 2.6 `Enums.csv` 追加

`ItemKind,1,材料`（仅此一档；后续丹药/图纸等尾部追加）。
