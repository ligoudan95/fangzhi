## 1. 时间模型（冻结）

1. **内部唯一时间源**：UTC Unix 整秒。持久化、结算、游标、季节推算只用该值。
2. **本地时间仅用于展示与日历触发**：每日 12:00/20:00 凶兽潮按设备本地时区映射到当天的 UTC 区间；时区/DST 变化只影响"下一次事件的 UTC 区间"，不影响已结算事实。
3. **四季**：全局纪元 `SEASON_EPOCH_UTC_SEC`（落 GlobalConst，所有存档同季）起，每季固定 5 个本地日历日 = 432000 秒，春夏秋冬循环（idx % 4 → 0春 1夏 2秋 3冬）。纪元之前的 UTC 值钳制为第 0 季。
4. **时钟倒退**：观测时间 < `meta.last_observed_utc_sec` 时该次结算收益为 0、游标不回退、`clock_rollback_count += 1`；快进按单机宽容策略正常结算，但受各系统离线上限约束。
5. **通知与奖励解耦**：本地通知只是提醒；无权限/未送达/延迟不改变事件生成、胜负与奖励。离线错过的事件在下次开屏按时间顺序补结算。
6. **tick 基准**：300 秒；切片边界 = 下一 tick 整倍数、下一季边界、结束时刻三者取最小（`scripts/logic/utc_time_slicer.gd` 与 `src/logic/timeSlicer.ts` 镜像）。

## 2. 离线结算合同

1. **系统独立游标**：修炼/巡猎/村落生产/兽潮各持 `settlement.cursors.<system>_utc_sec`；同一 now 只结算 `[cursor, min(now, cursor+cap))`，超上限时间记入报告且游标直接推进到 now（防反复登录分段领取）。
2. **离线上限**：基础 12h，图腾二段 24h（作用域=全部系统；一级仓库=基础容量，`base×1.5^(level-1)`）。
3. **幂等**：每批结算生成唯一报告 ID `system_id:start:end`；写入存档成功（save_slot 返回新 generation）后该报告才可领取；同 ID 覆盖不重复发放。UI 已展示但写档失败时丢弃 next_state，保留旧内存态。
4. **满仓（软）**：资源可超上限保留，超量部分每满 24h 衰减 10%，按数量比例分摊、整数余数按 item_id 升序（确定性）。装备背包满走自动分解兜底（白绿蓝，docs/08 §9）。
5. **季节分段**：跨季结算按季边界切片分别套用季节系数。
6. **天气**：不进入 M4（仅预留 `rng.streams` 中的 `village_event` 流）。

【M4 未实现】村落生产/巡猎/修炼/兽潮的产出公式结算器（需 ItemBase/Recipe/SeasonWeather/StorageRule/Building 表先行，走表结构评审）；本档先冻结合同与底层（时间切片+存档）。

## 3. 存档规格

### 3.1 信封（envelope）

```json
{ "version": 1, "generation": 7, "checksum": "<sha256-hex>", "data": { ... } }
```

- `generation`：每次成功写入 +1；写入前校验文件当前 generation 与内存一致，不一致拒绝（并发写保护）。
- `checksum`：对规范化 JSON `{version, generation, data}` 计算 SHA-256 小写 hex；规范化 = 键递归排序、无缩进、完整数值精度（GDScript `save_service.gd` 内 `_canonicalize`）。

### 3.2 data（schema v1 摘要）

- `meta`：save_id / created_at / updated_at / last_observed_utc_sec / clock_rollback_count
- `player`：realm_id / realm_layer / cultivation
- `wallet`：三货币
- `pets[]`：instance_id / pet_id / level / exp / realm_breaks / aptitude_seed / nature_seed（只存实例与种子）
- `equips[]`：docs/08 §12 EquipInstance 契约（instanceId/equipId/quality/level/rollSeed/identified）+ equipment.pityCounters + appliedSettlementIds（M3 幂等落位）
- `village`：population / buildings / fields / mine_jobs / recipe_jobs / pet_conditions / storage
- `settlement`：cursors + pending_reports（报告 ID 同 ID 覆盖）
- `rng`：root_seed + streams[]（state/draw_count；battle/drop/aptitude/village_event/village_quality 五条独立流；UI/日志/调试只能用克隆）

不存：配置快照、时区、季节系数、计算后产率、词条展示值。

### 3.3 迁移链

- `SaveMigrations`：严格 `n→n+1` 注册表；发布后旧迁移函数不得重写，只能追加。
- 迁移前把原始字节备份为 `.pre_migrate_v<n>.bak`；任一步失败回滚并保留源档。
- 读取未来版本（file.version > 当前）拒绝并提示。

### 3.4 原子写与恢复

写入：`<slot>.json.tmp`（flush+close）→ 回读校验 → 旧主档轮转 `.bak` → tmp rename 为主档。任何一步失败不删除最后有效候选。
读取顺序：主档 → `.bak` → `.tmp`；损坏主档改名为 `.corrupt.<utc>` 留证。槽位：3 手动 + 1 自动；`import_slot/export_slot` 只做结构校验与 IO，不触发结算。

### 3.5 分层铁律

`SaveService`（infra）只做 IO/校验/迁移调度，不含任何收益计算；结算器在 logic（RefCounted）纯函数化，输入（状态, UTC, 配置, RNG 状态），输出 `{next_state, report, events}`；事件总线只在写档成功后发事实信号。
