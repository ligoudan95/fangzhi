## 1. 技术选型

| 项 | 选型 | 理由 |
|------|------|------|
| 引擎 | **Godot 4.7.1 + GDScript**（Compatibility 渲染器） | 2D/Control 适合竖屏放置游戏；低端 Android 友好；静态贴图、Tween、序列帧与粒子无需第三方运行时 |
| 数据 | 导表 JSON（开发）/ 二进制（发布）+ 代码生成 d.ts | 对接框架第 20 章管线 |
| 存档 | 本地 JSON + 版本迁移链 | 纯单机，无服务器 |
| 音频 | 引擎内置 + 分通道混音（17.4 五通道） | — |
| 版本管理 | Git；导出物 CI 产物 | — |

## 2. 分层架构

```
┌─ View 层：UI（场景/面板/组件）｜演出（掉宝光柱/突破/收妖）｜静态贴图/Tween/序列帧
├─ Logic 层：系统模块（灵宠/战斗入口/村落/任务/装备/经济/境界）
│             └─ 事件总线 EventBus（系统间解耦，禁止横向直接调用）
├─ Battle 层：独立确定性战斗引擎（可 headless 脱离引擎运行）
├─ Data 层：ConfigService（导表只读）｜SaveService（存档读写+迁移）
└─ Infra 层：时间服务｜音频服务｜资源加载｜ TapTap SDK｜日志
```

**关键约束**：
1. Logic 层模块间只通过 EventBus 通信（如"捕捉成功"→图鉴/任务/成就各自监听）
2. View 层零业务逻辑，状态由 Logic 推送（放置游戏 UI 状态多，单向数据流防漂移）
3. Battle 层不依赖渲染——headless 可跑 AI 模拟与平衡报表（02 §9）

## 3. 数据驱动（对接第 20 章）

- ConfigService 启动加载：首发配置全部随基础包安装；启动加载 GlobalConst/Text/RealmConfig/PetBase，主界面后再从本地包异步加载其余配置到内存
- 所有系统读表不写表；运行时数值 = 表配置 × 存档实例数据的计算结果
- 表结构变更流程见框架 20.8；代码侧只认 d.ts 生成物

## 4. 存档系统

| 项 | 设计 |
|------|------|
| 结构 | `{ version, player{realm, xiushou…}, pets[], equips[], village{builds, fields…}, quests{}, collection{}, timestamp }` |
| 原则 | **只存实例**（ID、等级、资质 roll、词条 roll、耐久），不快照配置（框架 20.7） |
| 迁移 | 迁移函数链 `migrate[n→n+1]`；旧档读入逐级升版；迁移失败回滚并备份原档 |
| 槽位 | 3 个手动存档位 + 1 个自动位（每次上线覆写）；导出/导入文件（TapTap 社区分享玩法存档） |
| 防损 | 写入原子性（临时文件+rename）；崩溃恢复上次自动档 |
| 防篡改 | 单机买断不做强校验；仅存档哈希防误损坏（防改档作弊不做——尊重单机玩家实验自由） |

## 5. 战斗引擎

- **确定性**：逻辑帧与表现帧分离；随机统一走 seeded RNG；输入=（双方编队快照+操作序列+种子）
- 同种子同输入必同结果 → 用途：荒皇大比对手模拟（对手由御兽使图鉴+战力生成，本地跑 headless）、战斗回放、自动化数值验收（02 §4.6 演算表可脚本化跑通）
- 表现层按逻辑事件队列播放（技能演出/受击/死亡），支持 1x/2x/跳过

## 6. 时间与放置系统

| 项 | 设计 |
|------|------|
| 内部基准 | 持久化与时长计算统一使用 UTC Unix 时间戳；离线收益 = 当前 UTC − 上次结算 UTC |
| 本地日历 | 只用于展示、每日/每周重置边界，以及把本地 12:00/20:00 映射为事件 UTC；时区变化不得重复发奖 |
| tick | 在线每 5 分钟结算一次（挂机/生产）；离线按时间区间一次性结算（≤离线上限） |
| 改时间作弊 | 检测到时间倒流按 0 结算并记录；同一事件实例 ID 只结算一次 |
| 长周期 | 四季固定 5 个本地日历日/季；凶兽潮每日本地 12:00/20:00，离线错过后在下次开屏按序结算 |
| 通知 | 本地系统通知仅作提醒；关闭、延迟或未送达不得改变事件生成、胜负与奖励 |

## 7. 包体与性能目标

| 指标 | 目标 |
|------|------|
| 首发基础包（TapTap 下载） | 包含完整首发玩法、配置、美术与音频；目标 ≤ 400 MB，安装后无需联网下载资源 |
| 加载策略 | 场景、纹理与 BGM 从本地基础包按需载入内存；“懒加载”不表示网络下载 |
| 远期分包 | PCK 按需下载仅用于可选 DLC，首发流程不得依赖 |
| 内存 | 低端机（4GB）峰值 ≤ 800 MB；同屏活动序列帧节点 ≤ 6、粒子 ≤ 120；禁止 4096² 常驻总图集 |
| 帧率 | 战斗 60fps / 村落 30fps（竖屏 1080×1920 基准） |
| 加载 | 冷启动 ≤ 5s（读到主界面） |

## 8. 目录结构（工程约定）

```
scripts/
  infra/          # 时间/音频/资源/事件总线/日志（Autoload）
  config/         # ConfigService + 生成的表类型
  battle/         # 确定性战斗引擎（纯逻辑，可 headless）
  logic/          # pet/ village/ quest/ equip/ economy/ realm/
  view/           # UI、场景编排、VFX 与动画播放
scenes/
  battle.tscn     # 结构化事件驱动的战斗演出
  ui/             # 掉宝结算、装备对比等组件
resources/
  config/         # 导表产物 JSON（构建回填，勿手改）
  themes/         # UI 主题
assets/
  art/  frames/  fx/  ui/  audio/
tests/            # TS 数值基准 + GdUnit4 + 对拍
src/battle/       # 保留的 TS 确定性数值基准
tools/export/     # 导表脚本（对接 12 文档）
```

## 9. 测试与 CI 策略

| 层 | 手段 |
|------|------|
| 导表 | 校验器 + 冒烟（框架 20.6），CI 必跑 |
| 战斗 | headless 单测：公式锚点（02 §4.6）、控制递减、捕捉率分布（蒙特卡洛 1e5 次对齐期望） |
| 经济 | 产消模拟：按境界日流跑 30 天虚拟玩家（06 §5 对表） |
| UI | 关键路径手测清单 + 真机竖屏适配（异形屏安全区） |
| 发布 | TapTap 测试位灰度（Phase 1 限量测试） |

## 10. 风险与备选

- Web 试玩版使用 Godot 同工程导出；Compatibility 渲染器保持跨端能力
- 静态贴图显存超预算时：按实际显示尺寸降采样，大型背景线程加载并及时释放；序列帧按《10-美术设计规范》§11 限量
- 存档膨胀（装备/词条多）：词条存 roll 种子而非全量值，按需展开
