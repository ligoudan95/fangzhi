## 1. 设计原则复述

- **掉落为主，锻造为辅**：战斗是装备第一来源，锻造炉定向补缺
- 词条深度取中度档（决策 #6）：刷子有毕业追求，放置不被词条海吓退
- 120 级后战力成长完全由本系统承载（02 §8.2）——梦魇装备等级开放式

## 3. 幸运值系统

```
稀有档（紫/橙/红）权重 ×(1 + 幸运值/1000)，随后全表归一化
幸运值来源：鹰图腾(+15%/+25%) + 图鉴完成度(每 5% 图鉴 +10) + 装备词条 + 称号
基准幸运 100 → 稀有权重 ×1.1；毕业幸运 500 → ×1.5（橙概率约 +50% 相对值）
```

## 4. 装备等级

```
普通掉落：装备等级 = 怪物等级 ±2
梦魇荒域：第 L 层怪物等级 = 120 + 2L（无上限）→ 装备等级开放式成长
基础主属性 = 部位基准 × (1 + 装备等级 × 0.04)
```

## 9. 分解与材料循环（全链路无废物流）

```
白/绿/蓝 → 自动分解 → 锻造石（强化燃料）
紫 → 手动分解 → 锻造石×3 + 词条结晶（洗炼石原料：结晶×2→洗炼石×1）
橙 → 献祭 → 传说精髓（升阶/觉醒）
红 → 献祭 → 神器碎片（觉醒）
重复套装件 → 献祭 → 套装精华（定向补件）
```

## 12. Phase 0 实现契约（M3，2026-09-12 定）

已实现（`src/equipment/` + `scripts/logic/equip_drop_*.gd` + `tables/EquipBase|AffixPool|EquipQuality`）：

- **生成顺序**：品质自然 roll → 保底覆盖 → 模板 → 装备等级 → 词条数 → 无放回词条选择 → 词条值 → 未鉴定实例
- **独立 RNG**：种子由 (rootSeed, settlementSeq, dropId, itemIndex, streamTag) 经固定 avalanche 派生；具名流 QUALITY/TEMPLATE/LEVEL/AFFIX_COUNT/AFFIX_SELECT/AFFIX_VALUE/PITY_INDEX；不接触战斗 RNG
- **dropCount = guaranteed attempts**：`StageConfig.dropCount` 即确定装备尝试次数；§9.7 来源系数在归一化下抵消、`equipDropChance` 未定，均暂不接入（数值批准后走表结构评审）
- **pityUnit = settlement**：一次结算至多推进一格；达到阈值强制至少一件 `pityQuality`；自然命中即清零；保底索引走独立流
- **quality 持久化为实例结果**：未鉴定仅 UI 隐藏，鉴定用已存 `rollSeed` 幂等重展开，不重 roll、不消耗随机流
- **等级结构化**：`equipLvMode=monster_level` + `equipLvOffsetMin/Max`；旧 `equipLvRule` 字符串仅显示兼容；梦魇表达式解析延后
- 词条 stat 唯一防重复；`requiredGroups` 组配额暂不强制（全 0），待设计确认后落表
- 对拍：100 种子 × 掉落区段（普通/精英保底连锁/Boss+鉴定）canonical log 逐行一致

已知缺口（后续里程碑，不阻塞 Phase 0 验收）：

- 橙红**威能行为**未实现（§8 PowerConfig 延期；橙红实例仍会掉落并保存 quality）
- 套装/升阶/觉醒、洗炼、强化、分解、黑市掉落来源行未落表
- Save 原子提交/幂等 appliedSettlementIds 随 M4 存档闭环接入（当前 pity/instance 已具备可序列化契约）
