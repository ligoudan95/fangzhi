## 1. 表头模板细则（所有 sheet 强制）

```
第1行：字段名（camelCase，英文）
第2行：类型（见 §2）
第3行：可见性  c=导出客户端 / s=仅内部 / cs=双端
第4行：中文注释（需求说明，唯一权威文档）
第5行起：数据行
```

**示例（PetBase 节选）**：

| petId | name | element | quality | template | aptAtk | captureNote |
|------|------|------|------|------|------|------|
| int | string | enum(Elem) | enum(Quality) | enum(Tpl) | array\<int>(2) | string |
| c | c | c | c | c | c | c |
| 主键，1001 起，永不复用 | 名称 | 五行（阴阳=6/7 预留） | 凡1灵2玄3荒4王5神6 | 定位模板 phys/mage/tank/support | [min,max] roll 范围 | 捕捉地点说明 |
| 1001 | 灰岩獒 | 3 | 2 | tank | 600;850 | 初始赠予 |

**禁止**：合并单元格／跨表公式／中文表头字段名／隐藏行携带数据。枚举集中定义在 `Enums` 表（一处定义全表引用）。

## 2. 类型系统

| 类型 | 写法 | 导出目标（TS） |
|------|------|------|
| 整数/浮点/布尔/字符串 | `int / float / bool / string` | number / boolean / string |
| 枚举 | `enum(Name)` | 生成 union 类型 |
| 定长数组 | `array<T>(n)`，单元格内 `;` 分隔 | T[] |
| 结构体 | `struct(Name)`，字段引用 Structs 表 | interface |
| 跨表外键 | `ref<TableName>`，导表时校验存在性 | number（+生成访问器） |
| 区间 | `array<int>(2)` 约定 [min,max] | [number, number] |

## 4. 核心表字段字典（除 PetBase 外的四张关键表）

### 4.1 GlobalConst

| key | 类型 | 说明 |
|------|------|------|
| key | string | 常量键（如 DEF_K=220、CRIT_BASE=0.05、OFFLINE_CAP_H=12） |
| value | float | 值（02 文档全部锚点参数落此表） |
| desc | string | 中文注释=变更理由 |

### 4.2 SkillConfig

| 字段 | 类型 | 说明 |
|------|------|------|
| skillId / name / element | int/string/enum | 主键／名称／属性（无属性=0） |
| effects | array\<struct(Effect)> | 效果列表：{type(03 §4 枚举), power, buffId, duration, chance} |
| selector | enum | 目标选择器（03 §4） |
| cd / rageCost / rageGain | int | 冷却回合／怒气消耗／怒气获取 |
| learnLv | int | 习得等级 |

### 4.3 DropRule

| 字段 | 类型 | 说明 |
|------|------|------|
| dropId | int | 主键，StageConfig/BeastTide 引用 |
| source | enum | 野怪/精英/Boss/凶兽潮/异变/黑市/梦魇（08 §2 矩阵） |
| weights | struct | 六品质权重 + 幸运值适用开关 |
| pity / pityCount | enum/int | 保底类型与次数（橙 20/橙 10 等） |
| equipLvRule | string | 装备等级规则（含梦魇 `120+2L`） |

### 4.4 StageConfig

| 字段 | 类型 | 说明 |
|------|------|------|
| stageId / mapId / order | int | 主键／荒域／顺序 |
| waves | array\<ref<EnemyGroup>> | 波次 |
| dropId | ref<DropRule> | 掉落 |
| power | int | 推荐战力（02 §8.3 曲线锚点） |
| captureable | bool | 是否含可捕捉野怪 |

## 5. 工具选型决策矩阵（Phase 0 定稿）

| 维度 | Luban（开源） | 自研 Node 脚本 |
|------|------|------|
| 接入成本 | 中（C# 工具链） | 低（团队 TS 栈） |

## 6. 校验规则库（规则 ID 化，CI 输出报告）

| ID | 层级 | 规则 |

## 7. CI 流程（Git 仓库）

```
表 PR → CI：导表（校验 V-1xx~3xx）→ 生成 JSON+d.ts → 单测（公式锚点/蒙特卡洛捕捉率）
      → 平衡报表（V-4xx）→ 冒烟（V-501）→ 人工 review 表 diff（框架 20.8）→ 合并
```

导出物（JSON/d.ts）作为 CI 产物回填 `assets/resources/config/`，不手改。

## 8. 存档迁移规范（07 §4 实现细则）

- 存档 `version` 与表版本独立；表结构变更影响存档字段时**必须**新增迁移函数并补迁移测试
- 迁移链单调递增，禁止跳写（`migrate_3_to_4` 不允许直接改成 `migrate_3_to_5`）
- 废弃字段保留读兼容 ≥ 2 个版本；ID 永不复用（V-302）保证旧档引用永不悬空

## 9. DLC / 赛季表规范

- DLC 只允许：新增行、新增表、新增枚举**值**（追加在尾部）；禁止改已有行语义
- 每张 DLC 新表带 `requiresDlc` 字段，主程序按购买状态过滤加载
- 赛季表（SeasonXxx）独立命名空间，赛季结束归档不删除
