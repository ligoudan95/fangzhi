# 10-美术设计规范

> **版本**：v0.2 定稿　**日期**：2026-09-12
> **依据**：《01-游戏整体框架设计》v1.0 第 16 章；决策 #4（混合产能：AI 打底+精修+关键外包）、#9（竖屏）；《04-灵宠图鉴》首发 12 只
> **范围**：风格指南、色彩编码、静态贴图与序列帧表现、灵宠/场景/UI/VFX 规范、资产管线、性能预算与验收
> **定稿决策**：全项目不使用 Spine、骨骼动画或对应运行时插件。表现以静态岩彩贴图为主，辅以 Tween、局部拆件、受限序列帧与少量粒子。

## 1. 风格指南（Guideline 锚点）

- **锚点句**："在野兽横行的荒原上，一群圆滚滚的凶兽"
- 三层反差：场景「荒」（粗粝岩彩）／角色「萌」（2.5~3 头身 Q 版）／特效「炫」（高饱和五行光）
- 内部参照系：三星堆青铜纹样（图腾纹）、《山海经》异兽图谱（形态）、仰韶彩陶（纹饰节奏）
- 视觉结构：低饱和土石场景承载高饱和五行瞬时反馈；角色剪影优先于内部细节
- 禁止项：赛博/机械元素、现代服饰、写实比例人体、日系赛璐璐平涂、大面积持续发光、无意义常驻动效

## 3. 表现技术定稿

### 3.1 技术栈与红线

| 项 | 定稿 |
|------|------|
| 角色主体 | 静态透明 PNG；必要时增加一张攻击极限姿态 |
| 常规动作 | Godot Tween 驱动位置、缩放、旋转、透明度与颜色 |
| 局部动作 | 头饰、耳、尾、翅、武器等少量拆件贴图独立 Tween |
| 序列帧 | `AnimatedSprite2D` / `SpriteFrames`；常规 4~8 帧，关键效果最多 12 帧 |
| 粒子 | 一次性 `GPUParticles2D` 为主；仅用于碎屑、尘埃和环境点缀 |
| 演出编排 | 简单反馈用 Tween；多轨关键演出用 `AnimationPlayer` |
| 禁止 | Spine、骨骼动画、骨骼运行时插件、实时 2D 灯光、粒子拖尾、全屏模糊/折射、多层 SubViewport 后处理 |

### 3.2 动画素材帧率与画面刷新率

- 角色待机序列：6~8fps；特效序列：8~12fps；关键异象最多 12fps
- 战斗目标刷新率 60fps、村落目标刷新率 30fps；素材帧率不等于画面刷新率
- 不为追求“流畅”增加补间序列帧，动势由 Tween 的速度曲线完成
- 同一角色同一时刻最多播放一个序列帧动画；离屏与被遮挡对象停止动画

### 3.3 演出分级

| 层级 | 适用事件 | 允许手段 |
|------|------|------|
| L0 常驻 | 待机、村落呼吸感 | 低频 Tween、少量环境粒子；不震屏、不闪屏 |
| L1 常规 | 普攻、受击、收获、按钮 | 位移/缩放/变色、单个通用特效、短音效 |
| L2 技能 | 主动技、暴击、稀有产出 | 五行纹样、短序列帧、轻震屏、强化音效 |
| L3 高潮 | 绝技、捕捉结果、橙红掉落、突破 | 短时背景压暗、组合模板、受控全屏反馈；必须可跳过或加速 |

除 L3 外，不使用全屏颜色覆盖。强反馈结束后 0.2s 内恢复常态，避免放置战斗持续闪烁和视觉疲劳。

## 4. 灵宠设计与资产规格

### 4.1 造型规范

| 规范 | 要点 |
|------|------|
| 头身比 | 幼兽 2.5 头身 → 成兽 3 头身 → 完全体/太古体允许 3.5 头身 |
| 属性外显 | 五行特征固定落位：角/爪/皮毛/尾；火=赤羽余烬、水=鳞湿雾、金=电弧纹、木=花叶藤、土=石壳岩甲 |
| 剪影优先 | 战斗有效高度 ≤ 96px 时仍能辨识种族（验收硬标准） |
| 阶段差异 | 五阶段逐步增加灵纹、局部发光、专属部件、全身图腾与光环 |
| 异色兽 | 色相偏移 ≥ 30° + 特效换色，形态不变 |

首发 12 只的属性外显：灰岩獒（土·岩甲纹）、桃夭狐（木·桃瓣尾）、藤蔓妖（木·藤本）、灰羽雀（木·灰羽青翎）、朱羽雉（火·霞尾）、火岩犼（火·熔岩裂纹角）、雷纹貂（金·电弧纹皮毛）、啸月狼（金·雷啸鬃）、玄冰鲤（水·冰鳞）、雪魅（水·雪雾半透明）、石甲貔（土·石壳背甲）、地听犬（土·巨耳）。

### 4.2 单只灵宠交付

```text
art/pets/pet_1001_huiyan_ao/
├─ portrait_stage1.png       # 图鉴/结果页源图，透明底，最长边 2048px
├─ battle_idle_stage1.png    # 战斗静态主体，运行时最长边建议 ≤ 1024px
├─ battle_attack_stage1.png  # 可选；轮廓变化明显时提供
├─ fx_mask_stage1.png        # 可选；局部属性发光蒙版
├─ parts/                    # 可选；耳/尾/翅等不超过 3 个拆件
└─ frames/                   # 可选；主推宠的低帧序列
   ├─ idle_00.png ... idle_03.png
   └─ attack_00.png ... attack_05.png
```

- 立绘源文件可以 2048px 交付；运行时按使用尺寸生成降采样版本，禁止直接在战斗中加载 2048² 原图
- 阶段形态通过替换静态主体和复用通用动作实现，不为每阶段制作完整动作集
- 阴影使用 2~3 个通用椭圆模板；普通光环使用通用图腾贴图换色
- 拆件只服务于显著轮廓动作，不得把整只角色拆成骨骼式零件系统

## 5. 角色动作规范

| 动作 | 实现 | 时长/频率 |
|------|------|------|
| 待机 | 上下 3~5px + Y 轴缩放 `1.00→0.985→1.00`；主推宠可选 4 帧序列 | 2s 循环，错峰启动 |
| 物理攻击 | 后撤压缩 → 前冲 → 可选切攻击姿态 → 回位 | 0.35~0.45s |
| 法术攻击 | 下沉蓄势 + 属性蒙版亮起 + 前方符纹 | 0.45~0.60s |
| 受击 | 受力方向偏移 6~10px + 闪白 + 2°~4° 倾斜 | 0.18~0.22s |
| 倒下 | 去饱和 + 下沉 20px + 淡至 35% | 0.60s |
| 替补 | 阴影先落位，主体侧滑入场并轻微过冲 | 0.45s |
| 锄地/镐击/锤击 | 静态主体围绕支点旋转与位移；工具可为单独贴图 | 1.2s 低频循环 |

- 普通灵宠只需 `battle_idle` 即可完成全部基础动作
- `battle_attack` 与序列帧为增强项，不得成为玩法接入的前置条件
- 同屏待机循环必须错峰，禁止所有单位同相位呼吸

## 6. 场景与村落表现

- 透视：2.6D 斜 45°村落单屏；关卡背景使用远景/主体/前景三层静态贴图
- 每荒域“一主色一地貌”：黑风林=浓雾巨树、赤炎谷=熔岩裂谷、雷鸣泽=雷暴湖、北冥冰原=极光冰原、黄壤坡=黄土沟壑、万兽荒原=五行混搭+巨兽骸骨
- 村落三阶段共用构图，通过建筑状态贴图与分区解锁成长；不做自由旋转或重城建镜头
- 建筑最少提供“正常/生产中/完成”三态；生产反馈优先换图、图标飞入与局部亮起
- 四季使用季节背景变体 + 环境粒子；不使用运行时全屏 LUT
- 旗帜、炊烟、树叶、水面允许 4 帧、6fps 小循环；远景和离屏对象保持静态
- 村落同屏活动序列帧节点 ≤ 6；常驻环境粒子建议 40~80，硬上限 120

## 7. UI 规范（竖屏 1080×1920）

| 项 | 规范 |
|------|------|
| 材质语言 | 按钮=石板浮雕；面板=兽皮木框；装饰=骨珠/羽毛/绳结 |
| 安全区 | 异形屏上下各留 80px，并动态读取设备 SafeArea |
| 单手区 | 高频操作位于屏幕下 2/3；战斗控制固定在底部 |
| 字号层级 | 28/32/40/52 四级；正文 32 为移动端可读底线 |
| 信息密度 | 主界面常驻按钮 ≤ 8 个；二级功能收纳 |
| 页面切换 | 160~220ms 推入/淡入；不做长距离弹跳 |
| 按钮反馈 | 按下位移 2px，释放可发 4~6 粒尘埃 |

- 掉宝开箱结算屏：未鉴定件逐件翻牌，紫色以上停顿，橙色以上停顿 0.5s 后揭示
- 装备对比浮窗：词条差异红绿高亮，同时使用增减箭头，不能只依赖颜色
- 红点分提示/可领取/强提醒三级；普通红点静止，可领取只呼吸两次，音频仅强提醒触发
- 提供“减少动态效果”：关闭震屏、快速闪烁和常驻粒子，L3 演出改为不超过 0.8s 的摘要版

## 8. 战斗演出规范

### 8.1 战场结构

```text
BattleView
├─ BackgroundLayers        # 三层静态背景
├─ Battlefield             # 仅该容器参与震屏
│  ├─ AllySlots            # BattleActorView ×3
│  └─ EnemySlots           # BattleActorView ×3
├─ FxLayer                 # 池化序列帧/贴图特效
├─ NumberLayer             # 池化伤害与治疗数字
├─ ScreenFx                # 闪白、压暗，不覆盖 HUD 可读信息
└─ HUD                     # 血条、状态、速度/跳过/捕捉控制
```

当前文本战报缩为底部可展开区域，战斗主体使用 2×3 站位。View 只消费结构化战斗事件；日志继续用于对拍和复盘。

### 8.2 通用反馈

| 事件 | 视觉表现 | 预算 |
|------|------|------|
| 普攻 | 角色前冲 + 命中闪白 + 目标轻偏移 | 0.25s，8~12 粒 |
| 物理技能 | 碎岩扇面 + 冲击圆环，按五行换色 | 0.35~0.55s，≤24 粒 |
| 法术技能 | 图腾亮起 + 符纹上扫 + 命中 | 0.50~0.70s，≤32 粒 |
| 暴击 | 粗描边伤害字 + 80ms 表现停顿 + 4~6px 轻震 | 不冻结逻辑结算 |
| 治疗 | 木纹上升 + 绿色数字 + 短时提亮 | 0.45s，≤16 粒 |
| 护盾 | 赭黄石环闭合 + 护盾条出现 | 0.35s，无常驻粒子 |
| 状态 | 图标放大落位 + 脚下对应色短闪 | 0.25s |
| 控制 | 冰壳/电纹/锁纹静态覆盖 + 低频呼吸 | 同时只显示一个主覆盖 |
| 倒下 | 去饱和、下沉、岩粉散开 | 0.60s，≤20 粒 |
| 绝技 | 背景压暗 35% + 静态立绘切入 + 组合五行模板 | 常规版 ≤3s，摘要版 ≤0.8s，≤64 粒 |

### 8.3 通用 VFX 模板

首批只生产下列 10 个模板，技能通过贴图、方向、比例和五行色组合，不为每个技能独立制作整套序列：

`hit_slash`、`hit_crush`、`spell_rune`、`projectile_orb`、`heal_rune`、`shield_ring`、`control_overlay`、`death_dust`、`damage_number`、`screen_flash`。

## 9. 关键演出定稿

### 9.1 收妖葫芦

1. 目标压缩为五行色剪影，沿曲线飞入葫芦，0.8s
2. 葫芦使用闭合静态图，通过旋转 Tween 摇晃三次，1.2s
3. 成功：切开启图，金色契纹放大，4~6 帧闪光，展示灵宠立绘并播放专属叫声
4. 失败：播放 4~6 帧灰烟，目标从葫芦位置弹回战场
5. 捕捉率只在祭出前显示；揭晓期间隐藏数字，结果由 battle 事件提供，演出不得重新判定

### 9.2 掉宝与结算

| 品质 | 演出 |
|------|------|
| 白/绿 | 图标落袋 + 0.3s 轻扫光 |
| 蓝 | 单张细光柱纵向拉伸 0.6s + 卡片升起 |
| 紫 | 细光柱 + 三枚符纹依次亮起 + 三连上行音 |
| 橙 | 粗光柱达到屏幕 60% 高 + 0.3s 震屏 + 卡片停顿 0.5s；总时长约 1.6s |
| 红 | 环境骤静 + 背景压暗 + 8~12 帧巨兽异象剪影 + 红光；总时长 2~2.5s |

翻牌使用正反两张静态卡面做 `scale.x 1→0→1`，不使用 3D 翻转。掉宝音画时间轴以《11-音乐音效设计》§4 为准。

### 9.3 其余高潮

- 突破：灵纹逐一点亮 1.5s → 白闪换静态形态图 → 立绘定格 0.5s
- 凶兽潮预警：屏幕边缘红光呼吸 + 图腾警示纹 + 号角；禁止持续震屏
- 荒皇加冕：雕像静态分层落位 + 村民/灵宠贴图分组跳起欢呼 3s；不要求逐角色动画

## 10. 资产与导入管线

### 10.1 命名

```text
art/pets/pet_1001_huiyan_ao/       # 灵宠静态图与可选序列帧
art/scenes/area_heifenglin/         # 荒域三层背景
frames/fx_fire_skill_a/             # 特效序列：fx_{属性}_{类型}_{编号}
fx/common/fx_hit_slash.tscn         # 通用 VFX 场景
ui/panel_equip_compare/             # UI：panel_{功能}
audio/sfx_drop_orange.ogg           # 音频：sfx_{事件}
```

### 10.2 图集与导入

- 小型角色帧、VFX 帧和 UI 图标按模块进入 1024² 或 2048² 图集；禁止跨功能制作超大总图集
- UI 图标使用 Lossless；大型背景和大尺寸角色运行时图使用移动端 VRAM 压缩
- UI 与固定尺寸 2D 图关闭 mipmap；透明贴图开启 Fix Alpha Border；默认线性过滤
- 大型背景进入页面前可线程加载；离开页面后释放非共用资源
- `.tres` 仅存主题、`SpriteFrames`、动画和粒子等表现资源，不承载玩法数值
- 资产交付物 = 分层源文件 + 导出 PNG/序列帧 + 对应 `.import`/`.tres`/`.tscn` + assetPath 表更新

### 10.3 AI 辅助制作

```text
AI 打底（锁头身比/岩彩质感）
→ 人工精修（统一描边线宽 3px、校准五官与剪影）
→ 属性外显件与关键姿态人工修正
→ 序列帧逐帧清理轮廓和锚点
→ 色彩校准与运行时尺寸检查
```

- 每族先完成一只标定样本，再批量生产
- 主视觉、荒皇加冕、太古凶皇等 5~8 张关键图外包定制
- AI 生成序列帧不得直接入库，必须检查轮廓跳变、部件增减和锚点漂移

## 11. 性能与体量预算

| 指标 | 目标/红线 |
|------|------|
| 同屏活动序列帧 | 建议 ≤4，硬上限 6 |
| 单序列帧 | 常规 4~8 帧，关键最多 12 帧 |
| 同屏活动粒子 | 建议 ≤80，硬上限 120 |
| 单技能粒子 | 普通 ≤24，范围 ≤40，绝技 ≤64 |
| 村落常驻粒子 | 建议 40~80，硬上限 120 |
| 战斗角色运行时纹理 | 单张最长边建议 ≤1024px，按实际显示尺寸降采样 |
| 图集 | 单张建议 1024²/2048²；禁止 4096² 常驻总图集 |
| Phase 0 视觉资产 | 首屏建议 35~50MB；全量建议 ≤80MB |
| 帧率 | 中端机战斗 60fps；低档 30fps；村落 30fps |

- 伤害数字、命中特效、光柱、飞行资源图标全部池化
- 常驻粒子 `fixed_fps = 30`；低档通过 `amount_ratio` 降为 50%
- 震屏只移动 `Battlefield`，HUD 与安全区不移动
- 全屏明暗只使用一个 `ColorRect`；不得叠加多个全屏材质
- 表现随机使用事件序号哈希或独立视觉随机流，禁止消耗战斗/掉落/资质正式 RNG

## 12. 验收标准（Checklist）

- [ ] 全库无 Spine/骨骼运行时、骨骼资产或插件依赖
- [ ] 剪影测试：战斗有效高度 96px 时首发 12 只全部可辨
- [ ] 色彩测试：随机抽 20 图按 §2 校验，目标 ΔE ≤ 10
- [ ] 序列帧测试：无轮廓跳变、部件增减、锚点漂移和透明边黑边
- [ ] 竖屏适配：1080×1920、上下 80px 安全区及异形屏通过
- [ ] 单手可达：高频按钮全部处于屏幕下 2/3
- [ ] 动态减弱：关闭震屏/快速闪烁/常驻粒子后，所有玩法信息仍完整
- [ ] 确定性：同种子重播的事件顺序一致，表现不消耗正式随机流
- [ ] 性能：橙装演出中端机 ≥55fps；低档战斗 ≥30fps；峰值不突破 §11 红线
- [ ] 资源：无战斗场景直接加载 2048² 角色源图，无 4096² 常驻总图集
- [ ] AI 件抽检：每批 20% 人工审风格漂移；不合格整批返修

---

*产能规划：Phase 0 为 8 只×1 阶段，Phase 2 为 40 只×3 阶段。静态主体是必交付项；攻击姿态、拆件和角色序列帧均为按重要度增配项。*
