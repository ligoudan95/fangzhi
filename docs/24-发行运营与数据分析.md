## 2. 发布节奏

1. **限量测试**（Phase 0 收口后）：TapTap 测试位，100-500 人，2 周；目标=docs/16 §6 指标 + docs/20 §5 崩溃门禁。
2. **首发**：测试数据复盘 → 定稿包 → 商店页上线。
3. **首发后 4 周**：每周观察评论区三类主题（数值卡点/坏档/设备兼容），P0 响应 ≤48h。
4. **DLC/赛季**：仅在存档迁移链验证通过后发布（docs/12 §迁移原则），季度节奏【待确认】。

## 3. 版本号与补丁流程

- 版本号 `主.次.修`：主=存档结构/DLC 级变更；次=内容更新；修=修复。`version.gd` 单一真源，商店包名后缀对齐。
- 补丁流程：hotfix 分支 → check_all 全绿 → docs/14 台账记风险关闭 → 出包 → 商店整包更新（纯单机无热更，docs/13 §9）。
- 回滚：商店渠道回退上一版本包；存档向后兼容由"次"版本不破坏信封保证（未来版本拒绝读取策略见 docs/15 §3.3）。
- 运营红线：不做削弱性 hotfix 调数值（docs/06 §9）；数值调整随"次"版本并附 changelog。

## 4. 可选埋点事件字典（仅当 TapTD 决策通过，docs/21 §1）

| 事件 | 属性 | 用途 |
|---|---|---|
| session_start/end | 时长、版本 | 留存 |
| quest_complete | questId、耗时 | 主线卡点 |
| stage_result | stageId、outcome、回合数 | 关卡流失/平衡 |
| drop_settled | dropId、品质计数（不含实例明细） | 掉宝参与 |

约束：≤4 类事件；无设备标识符之外的个人数据；离线缓存上限 7 天；用户可一键清除【待外部确认：TapTD 能力边界】。
**不接入埋点时的替代**：限量测试受控试玩脚本（docs/16 §6）+ 评论区人工归类，每周复盘一次。
